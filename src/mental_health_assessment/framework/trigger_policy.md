# Trigger Response Policy

This document defines when the system should generate an assessment response.

Assessments may be initiated either automatically by the application or explicitly by the user. This document defines the triggering rules for both mechanisms.

It does not define how the assessment is generated or interpreted. Those
responsibilities belong to the corresponding Prompt.

**Behavioural Assessment Version 1 (V1)** is the temporary assessment system used after the user's personalized baseline has been established but before the Adaptive Anomaly Detection module becomes active. During this period, assessments are generated by interpreting the user's journals, parameter values and personalized baseline value ranges.

**Behavioural Assessment Version 2 (V2)** is the permanent assessment system used once the Adaptive Anomaly Detection module becomes active. During this period, assessments primarily interpret the anomalous parameters identified by the anomaly detection module while using the user's journals and personalized baseline as supporting context.

For brevity, the remainder of this document refers to these systems simply as **V1** and **V2**.

---

# V1 Trigger Policy

## Purpose

The V1 Trigger Policy operates during the temporary V1 period,
after the user's initial baseline has been established and before the
anomaly detection module becomes active.

It determines when a V1 assessment should be generated.

---

## Automatic Trigger

Immediately after Entry 20, the system shall automatically generate the
user's first behavioural assessment.

This assessment establishes the user's initial behavioural snapshot and
introduces the assessment system. No user request is required.

---

## User-Requested Trigger

After the initial assessment, the user may request a V1 assessment
at any time before V2 becomes active.

Whenever such a request is received, a new V1 assessment shall be
generated.

Each requested assessment should be treated as the next point in the
user's behavioural timeline.

The behavioural interpretation, comparison with previous assessments,
journal analysis and recommendation generation are performed by the
V1 Prompt.

---

# V2 Trigger Policy

## Purpose

The V2 Trigger Policy operates once anomaly detection becomes
active.

It determines when a V2 assessment should be generated.

---

## Automatic Trigger

Whenever the anomaly detection system determines that the application's
automatic assessment conditions have been satisfied, the system shall
generate a V2 assessment without requiring a user request.

The precise trigger conditions are defined by the anomaly detection
system rather than this document.

---

## User-Requested Trigger

The user may request a V2 assessment at any time.

Whenever such a request is received, a V2 assessment shall always
be generated, regardless of whether automatic trigger conditions have
been satisfied.

This allows the user to obtain an updated behavioural assessment even
during relatively stable periods.

The behavioural interpretation, temporal analysis, comparison with
previous assessments, journal integration, assessment memory and
recommendation generation are performed entirely by the V2 Prompt.

---

# Design Principle

The Trigger Policy answers only one question:

> **When should an assessment be generated?**

Everything concerning behavioural reasoning, information retrieval,
comparison, explanation and response construction belongs to the Prompt.
